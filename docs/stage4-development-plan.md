# 阶段 4：出口节点与受限网络能力

阶段 4 从 `main@8915a6c` 开始。阶段 1 至 3 已提供受控制器签名保护的
分流路由、DNS、点对点加密会话和 Relay 回退；本阶段在不削弱这些边界的前提下，
增加**用户本机显式选择**的出口节点和受限网络回退。

## 目标

1. 管理员能够把已授权成员声明为 IPv4、IPv6 或双栈出口候选。
2. 成员设备只能在本机明确选择某个已签名出口后，才安装默认路由。
3. 默认路由、DNS、kill switch、出口转发和 NAT 必须可事务应用、可撤销，且失败时
   不保留可能泄漏流量的半配置状态。
4. 出口节点只转发已由控制器授权的成员流量；不能仅因存在某条普通自定义路由就
   获得出口权限。
5. 在 UDP 不可用或被限制的网络中提供 TURN/TCP/TLS 回退；中继仍只处理密文，
   不持有虚拟网络密钥。

## 非目标

- 不把任意网络的默认路由自动推送给所有成员。
- 不在未经管理员启用的节点上打开系统 IP forwarding、NAT 或防火墙规则。
- 不把真实服务器地址、登录信息、令牌、私钥、邀请码或抓包内容写入仓库、测试
  inventory、日志或 CI 产物。
- 不以模拟执行器或本地单元测试替代真实 Windows/Linux 网络验收。

## 协议与迁移

默认路由改变了节点可见的网络边界，不能通过删除既有 `0.0.0.0/0` / `::/0` 拒绝
逻辑来实现。策略清单将升级为带版本号的出口节点扩展：旧清单继续按旧签名载荷
验证；新清单只由升级后的 Controller 签发。升级后的 Agent 若无法验证新策略，必须
清除该策略产生的路由和 DNS，而不是沿用未知语义的默认路由。

出口候选的签名信息至少绑定：网络 ID、网关设备 ID、IPv4/IPv6 能力、成员证书、
授权 epoch、策略 epoch、签发时间和过期时间。客户端的本地选择不得被 Controller
强制开启，且每个地址族同一时刻最多选择一个出口。

## 实现顺序

### 4A：签名出口授权与本地选择

- 在 `meshlake-core` 中引入版本化的出口候选和本地选择数据模型。
- 扩展 Controller 的成员出口授权和策略签发接口；撤销成员、出口资格或证书时必须
  同时撤销相关出口候选。
- 扩展 Agent 本地 API、CLI 与持久状态，提供选择/取消 IPv4、IPv6 出口的操作。
- 数据面只把已选、未过期、网络匹配且当前已授权的出口作为默认路由网关。
- 为旧清单、伪造出口、跨网络出口、过期授权、重复出口、撤销和选择回滚增加测试。

### 4B：平台默认路由、DNS 与 kill switch

- 扩展 Windows 和 Linux 策略投影，分别把分流路由与默认路由建模，保留可逆命令计划。
- DNS 仅在本机已启用出口且存在有效出口 DNS 策略时接管；退出或失败时恢复之前配置。
- kill switch 为用户本机显式开关：出口被选择但可信策略/隧道不可用时阻止经物理网络
  的非例外流量；Controller、Planet、Root、Relay 的必要引导流量必须保留最小例外。
- 任一清理或恢复失败时，关闭虚拟适配器并报告失败关闭，而不是保留不完整规则。

### 4C：出口节点转发与 NAT

- 以独立、管理员显式执行的本机操作启用/检查 IP forwarding。
- 为 Linux 提供 nftables/iptables 适配层，为 Windows 提供受控 NAT/转发适配层；二者
  都要记录可撤销的资源标识，禁止广泛清空用户既有规则。
- 出口节点数据面只接受来自当前控制器授权成员、目标为外部地址的流量；回程包必须
  匹配已建立的转发状态，且不能被注入到其他虚拟网络。

### 4D：TURN/TCP/TLS 回退与观测

- 定义独立版本化 TURN 配置与凭据分发接口；短期凭据不写入命令行或持久日志。
- 按 UDP 直连、UDP TURN、TLS TURN、现有加密 UDP Relay、MeshLake TLS Relay 的固定顺序回退。明文 TCP TURN 不得进入数据面，因为会暴露短期 REST 凭据。
- 在会话观测中仅暴露路径类别、失败原因类别和计数器，不暴露 TURN 凭据、端点或业务包。

### 4E：统一验收

所有 4A 至 4D 完成并通过离线单元/集成测试后，再对经授权、可丢弃的 Windows、Linux
和公网测试节点集中执行：双栈直连、直连转 Relay、Root/Relay 故障切换、出口 IPv4/IPv6、
DNS/killswitch、NAT 清理、TURN/TCP/TLS 与异常恢复。真实验收的 inventory 只保存主机
角色和外部秘密引用；秘密本身不进入仓库。

## 完成标准

- 普通分流网络不因版本升级或策略更新意外获得默认路由。
- Controller、Agent、数据面和平台投影均验证出口授权，任一层不满足即失败关闭。
- 所有平台命令均具有对应撤销路径，并对部分失败、撤销失败和服务重启有测试覆盖。
- 真实测试报告仅包含版本、提交、场景结果、时长、脱敏日志和计数器。

## 当前实现状态

4A 至 4D 的核心代码、离线单元测试、release 构建和受门禁的系统场景校验已完成。系统场景包含显式的 `turn-fallback` 编排，用于固定 UDP TURN、TLS TURN、UDP Relay 与 TLS Relay 的回退顺序；它不连接任何外部主机，也不能替代真实 coturn、Windows、Linux 或公网验收。

4E 仍须在用户明确授权的可丢弃实验环境中集中执行。真实 inventory 只能保存角色、可丢弃标记和非秘密连接引用；远程凭据、令牌、私钥、邀请码、Planet 内容和网络密钥不得写入仓库、命令行、日志或测试产物。
