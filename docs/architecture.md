# MeshLake 核心架构

## 产品边界

MeshLake 是三层（Layer 3）加密虚拟局域网。一台设备可同时加入多个彼此隔离的网络；每个网络拥有独立的网络 ID、虚拟地址前缀、成员证书和用于会话派生的网络 PSK。

当前核心不依赖图形界面。`meshlaked` 独占虚拟网卡和数据面，CLI/GUI 只访问 `127.0.0.1:51821` 的本机管理 API。关闭管理端不会中断已建立的虚拟网络。

## 组件

| 组件 | 职责 |
|---|---|
| `meshlaked` | Windows/Linux 无界面代理；管理 Wintun/TUN、加密数据包、NAT 穿透、根节点发现和中继回退。 |
| `meshlake-cli` | 无界面本机管理客户端；查询状态、控制网卡、配置 Planet，并通过一条邀请链接加入网络。 |
| `meshlake-controller` | 创建网络、分配虚拟地址、签发一次性邀请与 Ed25519 成员证书。 |
| `meshlake-root` | 类似行星根节点的已认证 UDP 会合服务；交换候选地址，不持有网络流量密钥。 |
| `meshlake-relay` | 可选公网 UDP 中继；验证成员证书，仅转发端到端加密载荷。 |
| `MeshLake` GUI | 可选 Windows 管理端；当前核心开发阶段不作为依赖。 |

## 信任与加密模型

1. 每台设备在本地生成长期 Ed25519 身份；私钥不发送给控制器、根节点或中继。
2. 一次性邀请链接携带控制器地址、网络 ID、短期令牌、钉扎的控制器公钥和 Planet 地址。
3. 控制器签发绑定设备 ID 与设备公钥的成员证书，并分配虚拟地址。
4. 通信双方使用 Ed25519 身份签名一次性 X25519 握手，HKDF-SHA256 将临时共享秘密与网络 PSK 混合，派生两个方向各自独立的 XChaCha20-Poly1305 会话密钥。
5. 数据帧使用会话 ID 和单调包序号构造唯一 nonce，并用 64 包滑动窗口防重放；会话最长使用 1 小时。
6. 中继只看到转发所需的网络、设备、会话和包序号以及密文，不持有网络 PSK 或会话密钥。
7. 根节点响应和 Planet 清单均需签名验证，不能仅依赖传输来源地址。

## 数据路径

客户端同时维护 IPv4 与 IPv6 UDP socket，并从根节点、中继、STUN、PCP、NAT-PMP 和 UPnP 收集候选地址。候选之间每 5 秒探测一次，以平滑 RTT 与失败惩罚评分：

1. 根据控制器签名成员证书建立虚拟 IP 到设备 ID 的地址目录；
2. 首次通信时建立设备身份签名的成对临时会话；握手期间最多缓存 8 个 IP 包并每秒重试；
3. 普通单播只发送给目标设备，广播和组播按成员逐一生成目标明确、使用不同成对密钥的加密帧；
4. 优先使用目标设备最近仍活跃且评分最低的端到端 UDP 直连路径；
5. 直连候选失效时，根据网络策略选择健康且优先级最高的 MeshLake 中继；
6. 单个根节点、中继或地址族失败不会终止整个传输工作线程；致命工作线程错误会在 3 秒后自动重建 socket 并重试。

详细规则见 [`unicast-routing.md`](unicast-routing.md) 和 [`pairwise-sessions.md`](pairwise-sessions.md)。

## 虚拟网卡模型

- Windows 使用一个 Wintun 三层适配器承载多个逻辑网络。
- Linux 使用 `/dev/net/tun` 创建 `meshlake0`，通过 `iproute2` 配置控制器分配的 IPv4/IPv6 地址。
- 网络隔离由网络 ID、地址前缀、成员证书和独立密钥实现，而不是为每个逻辑网络创建一张虚拟网卡。
